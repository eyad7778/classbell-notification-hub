# تشغيل Smart Student على Vercel

## سبب الخطأ الحالي

`SUPABASE_SERVICE_ROLE_KEY` مفتاح خاص يحتاجه الخادم لتنفيذ العمليات الموثوقة مثل إرسال الإشعارات. مفتاح Lovable Cloud مُدار داخليًا ولا يمكن نسخه إلى Vercel. لا تضع المفتاح العام مكانه، ولا تحذف فحصه أو تلغِ قواعد الصلاحيات.

## 1. نقل قاعدة البيانات مع الحسابات

1. أنشئ مشروع Supabase مستقلًا تملكه. هذا المشروع هو الوجهة الخارجية، وليس قاعدة Lovable Cloud الحالية.
2. في Lovable افتح **More → Database → Manage → Settings**.
3. من **Export project data** اختر **Export data**، ثم في بطاقة **Database** اختر **Export → Start export**.
4. نزّل التصدير من الرابط الذي يصلك بالبريد، أو من **More → Storage**.
5. استعد التصدير في المشروع المستقل باتباع إجراءات الاستعادة الرسمية للمزود. التصدير يحتوي على هيكل القاعدة والبيانات وحسابات المستخدمين وتجزئات كلمات المرور؛ عامله كملف حساس ولا ترفعه إلى المستودع.

لا تُشغّل ملفات التأسيس القديمة فوق نسخة مستعادة؛ النسخة تحتوي على الهيكل بالفعل. ملفات التصدير لا تحتوي على الملفات المرفوعة أو الأسرار أو إعدادات تسجيل الدخول.

نزّل الملفات المرفوعة من **More → Storage** وانقلها إلى مساحات التخزين الخاصة `lectures` و`receipts` في الوجهة مع الاحتفاظ بالمسارات وسياسات الوصول. لا تجعلها عامة.

فعّل تسجيل الدخول بالبريد وكلمة المرور في الوجهة. التطبيق يحوّل الهاتف إلى بريد داخلي تلقائيًا؛ لا تغيّر هذه الآلية. حافظ على إعداد التأكيد الفوري الحالي لأن هذه العناوين الداخلية لا تستقبل البريد. أعد ضبط عنوان الموقع وروابط إعادة التوجيه لتطابق رابط Vercel.

## 2. إعداد متغيرات Vercel

افتح مشروعك في Vercel ثم **Settings → Environment Variables**. أضف القيم من **المشروع المستقل نفسه** للبيئتين Production وPreview اللتين تستخدمهما:

| الاسم | القيمة المطلوبة |
| --- | --- |
| `VITE_SUPABASE_URL` | عنوان API للمشروع المستقل |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | المفتاح العام للمشروع المستقل |
| `SUPABASE_URL` | نفس عنوان API أعلاه |
| `SUPABASE_PUBLISHABLE_KEY` | نفس المفتاح العام أعلاه |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح `service_role` الخاص أو المفتاح السري `sb_secret_` للمشروع المستقل |
| `TELEGRAM_API_KEY` | توكن البوت الصادر من BotFather |
| `VAPID_PUBLIC_KEY` | المفتاح العام لزوج مفاتيح إشعارات الجهاز |
| `VAPID_PRIVATE_KEY` | المفتاح الخاص المطابق للمفتاح العام |
| `VAPID_SUBJECT` | جهة اتصال حقيقية بصيغة `mailto:` أو عنوان HTTPS |
| `GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON` | محتوى ملف JSON لحساب خدمة Google الذي يرفع الملفات إلى Drive |
| `GOOGLE_DRIVE_FOLDER_ID` | معرّف مجلد Drive الذي ستُحفظ فيه الملفات |

احفظ المفاتيح الخاصة في إعدادات Vercel فقط؛ لا تضف لها بادئة `VITE_` ولا تضعها في ملفات المستودع أو المحادثة. متغيرات `VITE_` تُضمّن أثناء البناء، ولذلك يجب إعادة النشر بعد تغييرها. لا تعتمد على وجود `.env` محلي ليتم نقله تلقائيًا إلى Vercel.

### إعداد رفع Google Drive المباشر

ارفع الملفات من نموذج إدارة المحتوى إلى الخادم، والخادم يرسلها إلى Google Drive. لإعداده على Vercel:

1. في Google Cloud فعّل **Google Drive API** وأنشئ حساب خدمة ومفتاح JSON له.
2. أنشئ مجلد Drive للمواد وشاركه بصلاحية **Editor** مع قيمة `client_email` في ملف حساب الخدمة.
3. أضف محتوى ملف JSON كاملاً إلى `GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON`، ومعرّف المجلد إلى `GOOGLE_DRIVE_FOLDER_ID` في إعدادات Vercel لكل من Production وPreview، ثم أعد النشر.
4. أضف القيمتين نفسيهما كأسرار خادم في Lovable إذا كان النشر المدار هناك يحتاج الرفع أيضاً.

لا تضع JSON في متغير يبدأ بـ `VITE_` أو في المستودع. الرفع من نموذج الإدارة يقبل الملفات حتى 2.5 ميغابايت لتناسب حدود طلبات وظائف Vercel. روابط الملفات تتبع صلاحيات المشاركة المضبوطة على المجلد في Google Drive.

حافظ على زوج VAPID نفسه إذا كانت لديك اشتراكات أجهزة سابقة؛ تغييره يتطلب إعادة ربط الأجهزة. ربط Telegram يحتاج إعادة توجيه webhook الخاص بالبوت إلى عنوان Vercel مع الحفاظ على التحقق من المتصل.

## 3. إعداد النشر

- Node.js: إصدار 22.12 أو أحدث.
- Framework Preset: **Other** إذا لم يتعرف Vercel على المشروع تلقائيًا.
- Build Command: `npm run build`.
- اترك Output Directory بدون تجاوز يدوي؛ إعداد Nitro الخاص بـ Vercel ينتج مخرجات Vercel المطلوبة، وليس موقعًا ثابتًا فقط.
- `vite.config.ts` يختار إعداد `vercel` للنشر الخارجي، بينما يظل نشر Lovable تحت الإعداد المدار الخاص به.
- اختر **Redeploy** بعد إضافة المتغيرات، مع إعادة بناء النسخة وليس إعادة استخدام نسخة مبنية بمفاتيح Cloud القديمة.

## 4. التحقق قبل الاعتماد على النسخة الجديدة

1. سجّل الدخول بحسابك الحالي وتأكد من ظهور الاسم والدور والبيانات المنقولة.
2. افتح حسابي وملفات المحاضرات وتأكد أن الصلاحيات ومساحات التخزين الخاصة تعمل.
3. جرّب ربط Telegram ثم أرسل إشعارًا من الإدارة وتحقق من وصوله.
4. جرّب «ربط هذا الجهاز» من الموقع المنشور على متصفح يدعم الإشعارات؛ على iPhone افتحه كتطبيق مضاف للشاشة الرئيسية.
5. افتح رابطًا داخليًا مباشرة ثم حدّث الصفحة للتحقق من سلامة التنقل.

لا يُعتبر الانتقال مكتملًا قبل إجراء هذه الاختبارات على رابط Vercel الفعلي.
